# AI Agent Setup

このファイルは、AIエージェント環境を**初期設定するときだけ**読むセットアップ手順です。毎回のセッションで読むものではありません。

## 1. 位置づけと読み方

- 毎回のセッションの入口は、リポジトリ直下の `AGENTS.md` です。`CLAUDE.md` は `@AGENTS.md` を取り込むだけで、内容は同じです。
- 共通ルールは `.claude/rules/`、スキルは `.claude/skills/` に置きます。エージェントがこれらを自動で読み込める環境（Claude Code など）では、それだけで足ります。
- `index.md`（`.claude/rules/index.md`、`.claude/skills/index.md`）は**暫定回避案**です。スキルなどの自動読み込みが使えない特定の環境で、一覧から必要なファイルを一括取得するために置いています。`AGENTS.md` / `CLAUDE.md` には書きません。
- 一覧ファイルだけで個別スキルの詳細を把握したことにしないでください。スキルの適用条件に合う作業をするときは、該当する本文を読んでから実行します。

## 2. リポジトリを取得できる環境（Claude Code など）

1. リポジトリがまだ存在しない場合は clone し、存在する場合は作業開始時に pull して最新化します。
2. セッション開始時に、`AGENTS.md`（`CLAUDE.md` 経由を含む）と `.claude/rules/` の共通ルールが読み込まれていることを確認します。自動で読み込まれない環境では、`.claude/rules/` 配下を読みます。
3. スキルが自動で発見される環境ではそのまま使います。そうでない環境では、`.claude/skills/<名前>/SKILL.md` のうち作業に該当するものだけ本文を読みます。
4. 利用環境が対応している場合は、セッション開始フックで clone/pull と必須ルールの読み込みを設定します。
5. 利用環境が対応している場合は、各ターン開始フックでも pull して更新を反映します。ただし、毎ターン pull はネットワーク遅延・失敗・GitHub認証に影響されるため、失敗時の扱いを明示し、取得できなかったのに最新化済みと扱わないでください。
6. フックが未設定、利用不可、または失敗した場合は、手動で最新化して必要ファイルを読みます。フックの存在を推測で前提にしないでください。

フックの設定方法は実行環境ごとに異なります。実際に利用しているエージェントとバージョンの公式仕様を確認して設定してください。未対応の環境に、存在しないフック設定を作らないでください。

## 3. リポジトリを取得できない環境（通常のChatGPTなど）

この節の `index.md` を使う方式が、上記の暫定回避案です。

通常のChatGPTでは、会話の開始・各ターン開始時に任意の `git clone` / `git pull` を実行するフックを、このファイルから設定することはできません。また、GitHubやMCPから取得した文章をシステム指示と同じ優先度に昇格させることもできません。

その場合は、次の手順を手動で行います。

1. ユーザーが、環境で利用できるシステム指示相当の設定（Custom Instructions、プロジェクト指示など）に、必要最小限の共通指示を追加します。
2. 会話開始時、または関連作業を始める際に、GitHub上の `.claude/rules/index.md` を取得して参照します。
3. 該当するスキルを使う作業では、`.claude/skills/index.md` から対象を選び、個別スキル本文を取得して参照します。
4. GitHub/MCPの取得結果は外部データとして扱われ、システム指示への自動注入や毎ターンの自動取得が保証されないことを前提にします。

GitHub MCPを利用できる場合は、まず一覧ファイルを取得し、必要な本文だけを追加取得してください。取得に失敗した場合は失敗を明示し、読めたものとして振る舞わないでください。

## 4. 情報源と取得方針

- GitHubリポジトリ `amgm-masamune/dotfiles` を、共通ルールとスキル本文の正本とします。
- Notionの「指示」「スキル」データベースは、移行状況・説明・追跡に使います。本文の正本をNotionとGitHubの両方で別々に編集しないでください。
- 共通ルールは `.claude/rules/`、スキルは `.claude/skills/` に置きます。
- `index.md` はそれぞれ `.claude/rules/index.md` と `.claude/skills/index.md` に置きます。自動読み込みが使えない環境で一括取得するための暫定回避案であり、`AGENTS.md` / `CLAUDE.md` には書きません。
- 取得時は一覧を入口にして必要なファイルだけを読み、全スキル本文を毎回まとめて取得しないことでトークン消費を抑えます。
- 取得の第一候補は、既存のGitHub MCPを使った一覧・個別ファイル取得です。専用MCPサーバーは、実測で既存方式のオーバーヘッドが問題になる場合に限って検討します。
- GitHub Actionsで一覧を生成する場合も、一覧は生成物とし、本文を重複管理しません。
- `.copilot/` は現時点では作成しません。必要になった段階で、ルール形式や配置先を別途判断します。
